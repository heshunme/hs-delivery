# Destination host acceptance

Use this for a later real-host trial, including when the user owns that acceptance. Local tests exercise helpers and fixture protocols; these scenarios establish the destination host's actual discovery, completion and recovery behavior. This checklist starts unexecuted.

Use a disposable project/task and the actual installed skill. Record machine/OS, host and CLI versions, skill commit, interpreter/dependencies, instruction source and chosen completion mechanism. Use real participant IDs from this task only. Run remote or externally mutating scenarios only within the trial's actual authorization.

| Scenario | Observable acceptance |
|---|---|
| Fresh start | The host reads existing repository rules and the installed recovery pointer; it finds the intended project conventions and task |
| Compaction/resume | In the first useful actions after each tested transition, the coordinator reloads the skill and current card, retaining the actual candidate, pending work and scope |
| One work round | A writer returns immutable versioned evidence; an independent reviewer inspects the actual candidate and its result reaches the assigned coordinator |
| Busy feedback | Feedback follows the host's supported path without replacing useful work; a feedback-dependent step waits at the named checkpoint |
| Completion while idle | The chosen supported path wakes the coordinator, or the recorded explicit-resumption path is used; no unsupported automatic wakeup is claimed |
| Background success/failure | An authorized long command or existing CI wait retains its actual exit, candidate/run identity and log; the callback leads to correct reconciliation |
| Missing result/interruption | A worker ending before publication or a deliberately interrupted task remains visible as pending; resume inspects existing artifacts before repeating work |
| Stop and cleanup | A pre-stopped command does not launch; a running owned command stops through its supported path; processes and host resources are reconciled |
| Closeout | Current review/gates/findings agree with the card; inbox results are disposed of and owned temporary resources are accounted for |

Save a per-trial copy of the results table under the task's acceptance records; this file stays a reusable checklist. Mark each row passed, failed, pending or inapplicable with a reason and evidence. A queue-specific row may be inapplicable to a native hand-back path. Use a separate binding and evidence for each host actually tested; success on one does not establish another host's behavior.

Retain failures with their environment and version, then append fix/retest evidence. Do not claim the checklist passed merely because local tests or format checks passed. A later host trial can finish the pending acceptance without rerunning unchanged local checks.
